# 监考事件体系

## 一、事件总览

监考事件是整个监考系统的核心数据流。每一个事件都对应着考生在考试过程中的一种行为状态变化。系统通过捕获、记录和分析这些事件，实现对考试行为的全链路监控。

### 事件分类

| 分类 | 事件 | 说明 |
|------|------|------|
| 页面可见性 | `exam_leave` / `exam_return` | 离开与返回考试页面 |
| 异常中断 | `leave_recovered` | 浏览器被杀后重进的补偿事件 |
| 设备方向 | `orientation_change` | 横竖屏切换 |
| 网络状态 | `network_offline` / `network_online` | 网络断开与恢复 |
| 刷新检测 | `refresh_attempt` | bfcache 恢复（页面刷新尝试） |

## 二、完整事件定义表

### 2.1 exam_leave — 离开考试页面

| 属性 | 说明 |
|------|------|
| **事件类型** | `exam_leave` |
| **触发条件** | `visibilitychange` → `hidden` 或 `blur` 且非输入框聚焦 或 `pagehide` |
| **数据结构** | `{ type, timestamp, tags }` |
| **风险意义** | 考生离开考试页面，可能存在切屏、查看其他资料等作弊行为 |

**详细触发逻辑：**

1. `document.visibilitychange` 事件触发且 `document.visibilityState === 'hidden'`
2. `window.blur` 事件触发且当前焦点不在 `<input>`、`<textarea>`、`<select>` 内
3. `pagehide` 事件触发（兼容 iOS Safari 后台挂起场景）

**tags 标记说明：**

| tag | 含义 |
|-----|------|
| `network_related` | 发生在 network_offline 后 30 秒内（可能因断网导致的离开） |
| `frequent_leave` | 短时间内高频离开（5 分钟内 leave ≥ 3 次） |

### 2.2 exam_return — 返回考试页面

| 属性 | 说明 |
|------|------|
| **事件类型** | `exam_return` |
| **触发条件** | `visibilitychange` → `visible` 或 `focus` 且已标记 hidden 或 `pageshow` |
| **数据结构** | `{ type, timestamp, duration, tags }` |
| **风险意义** | 考生返回考试页面，含离开时长，用于判断离开时间是否异常 |

**详细触发逻辑：**

1. `document.visibilitychange` 事件触发且 `document.visibilityState === 'visible'`
2. `window.focus` 事件触发且内部 `isPageHidden === true`
3. `pageshow` 事件触发（兼容 bfcache 恢复）

**tags 标记说明：**

| tag | 含义 |
|-----|------|
| `rapid_leave_return` | 离开时长 ≤ 5 秒（快速往返，可疑行为） |
| `long_leave` | 离开时长 ≥ 60 秒（长时间离开，高度可疑） |

**duration 计算规则：**
- `duration = timestamp - currentHiddenStart`
- 单位：毫秒（ms）

### 2.3 leave_recovered — 异常中断补偿

| 属性 | 说明 |
|------|------|
| **事件类型** | `leave_recovered` |
| **触发条件** | `startMonitoring` 时检测 sessionStorage 中 `currentHiddenStart` 存在 |
| **数据结构** | `{ type, timestamp, endTime, duration, tags }` |
| **风险意义** | 上次会话在 hidden 状态被终止（浏览器被杀后重进），自动补全离开时长 |

**详细触发逻辑：**

1. 考生重新进入考试页面
2. `startMonitoring()` 从 `sessionStorage` 读取持久化数据
3. 检测到 `currentHiddenStart !== null`，说明上次会话在离开状态被异常终止
4. 自动计算离开时长：`duration = now - currentHiddenStart`
5. 生成 `leave_recovered` 事件，`endTime` 为 sessionStorage 中保存的时间戳

**tags 标记说明：**

| tag | 含义 |
|-----|------|
| `long_leave` | 补全的离开时长 ≥ 60 秒 |
| `frequent_leave` | 属于高频离开序列的一部分 |

### 2.4 orientation_change — 设备方向变化

| 属性 | 说明 |
|------|------|
| **事件类型** | `orientation_change` |
| **触发条件** | `orientationchange` 事件 或 `resize` 检测到宽高互换 |
| **数据结构** | `{ type, from, to, timestamp }` |
| **风险意义** | 设备方向变化，可能暗示使用外部显示器或投屏 |

**详细触发逻辑：**

1. `window.orientationchange` 事件触发
2. 或 `window.resize` 事件触发且检测到 `innerWidth` 与 `innerHeight` 互换（原宽 > 原高 → 新宽 < 新高，或反之）

**方向值说明：**

| 值 | 含义 |
|----|------|
| `portrait` | 竖屏模式（高度 > 宽度） |
| `landscape` | 横屏模式（宽度 > 高度） |

**触发条件补充：**
- 部分浏览器不触发 `orientationchange`，通过 `resize` + 宽高比较兜底
- 仅当宽高比发生"互换"时才触发，避免普通窗口 resize 误触发

### 2.5 network_offline — 网络断开

| 属性 | 说明 |
|------|------|
| **事件类型** | `network_offline` |
| **触发条件** | `offline` 事件触发 |
| **数据结构** | `{ type, timestamp }` |
| **风险意义** | 网络异常，可能影响考试提交，同时与 leave 事件关联分析 |

**详细触发逻辑：**
- `window.addEventListener('offline', ...)` 捕获
- 同时记录到独立的 `networkEvents` 数组中
- 提交时合并到完整事件流中

### 2.6 network_online — 网络恢复

| 属性 | 说明 |
|------|------|
| **事件类型** | `network_online` |
| **触发条件** | `online` 事件触发 |
| **数据结构** | `{ type, timestamp }` |
| **风险意义** | 网络恢复，确认网络状态切换完成 |

**详细触发逻辑：**
- `window.addEventListener('online', ...)` 捕获
- 与 `network_offline` 配对使用，标记网络中断的时间区间

### 2.7 refresh_attempt — 页面刷新尝试

| 属性 | 说明 |
|------|------|
| **事件类型** | `refresh_attempt` |
| **触发条件** | `pageshow` 事件 `persisted === true` |
| **数据结构** | `{ type, timestamp, source }` |
| **风险意义** | 页面通过 bfcache 恢复（后退/前进），可能涉及刷新操作 |

**详细触发逻辑：**

```javascript
window.addEventListener('pageshow', (event) => {
  if (event.persisted) {
    // 从 bfcache 恢复，触发 refresh_attempt
    pushEvent({
      type: 'refresh_attempt',
      timestamp: Date.now(),
      source: 'bfcache'
    });
  }
});
```

**source 值说明：**

| 值 | 含义 |
|----|------|
| `bfcache` | 从浏览器后退/前进缓存恢复 |

## 三、事件去重与合并机制

### 3.1 三层去重策略

监考事件在高频场景下（如快速切屏）可能密集触发，系统通过三层机制控制事件质量。

```
原始事件流
    ↓
[Layer 1] 100ms 合并窗口（MERGE_WINDOW）
    ↓
[Layer 2] 500ms 去重窗口（DEDUP_WINDOW）
    ↓
[Layer 3] action 抢占（pending leave → return）
    ↓
最终事件流
```

### 3.2 机制详解

#### 100ms 合并窗口（MERGE_WINDOW）

```
场景：快速切屏
时间线：
  t=0ms   visibilitychange → hidden  → exam_leave
  t=50ms  blur                       → (合并，不产生新事件)
  t=80ms  pagehide                   → (合并，不产生新事件)
  t=100ms 合并窗口到期 → 输出单个 exam_leave
```

- 同类型事件在 100ms 内触发时合并为一个事件
- 以第一个事件的时间戳为准
- 避免同一行为被多次记录

#### 500ms 去重窗口（DEDUP_WINDOW）

```
场景：反复触发
时间线：
  t=0ms    visibilitychange → hidden  → exam_leave ✓
  t=300ms  visibilitychange → hidden  → 500ms 内，忽略 ✗
  t=600ms  visibilitychange → hidden  → 超过 500ms，重新记录 ✓
```

- 同一事件类型在 500ms 内只执行一次
- 使用时间戳比较，精确控制

#### action 抢占

```
场景：leave 后立即 return
时间线：
  t=0ms  visibilitychange → hidden  → 安排 exam_leave（pending）
  t=20ms visibilitychange → visible  → 抢占：立即执行 exam_leave
  t=21ms                              → 安排 exam_return
  t=21ms                              → 输出：exam_leave + exam_return
```

- 当 leave 事件处于 pending 状态时，若 return 事件到达
- 立即执行 leave（防止 merge window 期间事件丢失）
- 然后安排 return 进入 merge window
- 确保事件的时序正确性

### 3.3 MAX_EVENTS 限制

| 参数 | 值 | 说明 |
|------|----|------|
| `MAX_EVENTS` | `100` | 最大保留事件数 |

**超出处理：**
- 当事件数量超过 100 时，采用**头部截断**策略
- 丢弃最早的事件，保留最新的 100 条
- 确保存储和传输的可控性

**设计理由：**
- 100 条事件已足够覆盖考试期间的关键行为
- 避免极端异常情况下事件数量失控
- 保留最新事件有利于风险分析的实时性

## 四、事件生命周期

```
                    ┌─────────────┐
                    │  startMonitor │
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │  leave_      │
                    │  recovered? │──── 是 ──▶ 生成补偿事件
                    └──────┬──────┘
                           │ 否
                    ┌──────▼──────┐
                    │   事件监听   │◀──── 持续运行
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
         ┌─────────┐ ┌─────────┐ ┌──────────┐
         │ 合并去重 │ │ 执行事件 │ │ 持久化存储 │
         └────┬────┘ └────┬────┘ └────┬─────┘
              │            │            │
              └────────────┼────────────┘
                           │
                    ┌──────▼──────┐
                    │  flushEvents │
                    │  (提交时)    │
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │  上报后端    │
                    └─────────────┘
```

## 五、事件数据格式汇总

### 5.1 通用字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | `string` | 事件类型标识 |
| `timestamp` | `number` | Unix 时间戳（毫秒） |
| `tags` | `string[]` | 行为标签数组（可选） |

### 5.2 各事件特有字段

| 事件 | 特有字段 | 说明 |
|------|----------|------|
| `exam_leave` | — | — |
| `exam_return` | `duration: number` | 离开时长（毫秒） |
| `leave_recovered` | `endTime: number, duration: number` | 结束时间、离开时长 |
| `orientation_change` | `from: string, to: string` | 原方向、新方向 |
| `network_offline` | — | — |
| `network_online` | — | — |
| `refresh_attempt` | `source: string` | 来源（如 `bfcache`） |
