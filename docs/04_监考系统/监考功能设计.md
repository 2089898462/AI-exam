# 监考功能设计

## 一、监考系统概述

监考系统是 AI 考试系统的核心子模块之一，用于在考试过程中实时检测考生的异常行为、持久化监考数据、自动进行风险分析，并最终以 HR 可理解的方式展示监考结果。

- **开发阶段**：S8 阶段完成（S8.1 – S8.4.7）
- **核心能力**：事件检测、数据持久化、异常分析、HR 展示
- **设计目标**：构建一套端到端的监考闭环，从前端事件捕获到后端风险分析，再到 HR 端可视化呈现

## 二、设计目标

| 目标 | 说明 |
|------|------|
| 实时检测考试异常行为 | 捕获离开页面、切屏、旋转、断网等行为事件 |
| 持久化监考数据 | 使用 sessionStorage 实时写入，防止数据丢失 |
| 自动风险分析 | 后端基于事件数据自动计算风险等级 |
| HR 可理解展示 | 以时间线、风险摘要、审核建议的形式呈现 |

## 四、功能模块划分

### 模块 1：事件监听层

负责在考试页面中监听各类浏览器事件，捕获考生行为。

**监听的事件类型：**

| 事件 | 用途 |
|------|------|
| `visibilitychange` | 检测页面可见性变化 |
| `blur` / `focus` | 检测窗口失焦与恢复 |
| `pagehide` / `pageshow` | 检测页面隐藏与恢复 |
| `orientationchange` | 检测设备横竖屏切换 |
| `online` / `offline` | 检测网络连接状态 |

**关键特性：**
- 同时监听多种事件源，确保在不同场景下都能可靠捕获
- 对 iOS Safari、Android Chrome、bfcache 等场景做兼容性处理
- 支持事件标记（tags）用于后续风险分析

### 模块 2：事件合并层

在事件密集触发时进行合并与去重，避免产生冗余事件。

**核心机制：**

| 机制 | 参数 | 说明 |
|------|------|------|
| 100ms 合并窗口 | `MERGE_WINDOW = 100` | 同类型事件在 100ms 内合并 |
| 500ms 去重窗口 | `DEDUP_WINDOW = 500` | 同一动作 500ms 内不重复执行 |
| `scheduleAction` | — | 调度执行，支持 action 抢占 |
| action 抢占 | — | pending 的 leave 遇到 return 时，立即执行 leave 再安排 return |

### 模块 3：数据持久化层

使用 `sessionStorage` 实时写入监考数据，确保页面异常关闭后可恢复。

**核心能力：**
- **实时写入**：每次事件发生后立即序列化写入
- **异常恢复**：考生重新进入考试时，检测上次会话状态并补偿
- **数据补偿**：`leave_recovered` 事件自动补全离开时长
- **提交清理**：提交成功后清除缓存，提交失败则保留

**存储结构：**

```json
{
  "version": 1,
  "events": [...],
  "orientationEvents": [...],
  "networkEvents": [...],
  "leaveCount": 0,
  "totalHiddenDuration": 0,
  "currentHiddenStart": null,
  "isPageHidden": false,
  "savedAt": 1729000000000
}
```

### 模块 4：风险分析层

后端基于监考事件数据自动执行风险分析，计算风险等级。

**分析流程：**
1. 接收前端上报的监考数据
2. 执行 5 项检测规则（快速往返、长时间离开、高频离开、网络关联、刷新尝试）
3. 汇总行为标签与风险原因
4. 计算最大离开密度
5. 确定最终风险等级（normal / low / medium / high）

### 模块 5：展示层

HR 端监考详情页面，以直观的形式呈现监考结果。

**展示内容：**
- 风险等级徽章（颜色区分）
- 事件时间线（可视化呈现所有事件）
- 关键指标摘要（离开次数、总时长）
- 审核建议（根据风险等级动态生成）

## 五、移动端适配

### 5.1 兼容性处理

| 场景 | 处理方式 |
|------|----------|
| iOS Safari 后台挂起 | 通过 `visibilitychange` + `pagehide` 双重捕获 |
| Android 浏览器被杀 | `sessionStorage` 保留，重进时触发 `leave_recovered` 补偿 |
| bfcache（后退/前进缓存） | `pageshow.persisted=true` 触发 `refresh_attempt` 事件 |
| 方向变化检测 | 同时监听 `orientationchange` 和 `resize`（宽高互换判断） |
| 网络状态检测 | `online/offline` 事件 + `navigator.onLine` 兜底 |

### 5.2 iOS 特殊处理

iOS Safari 在页面进入后台时可能触发 `pagehide` 而非 `visibilitychange`，监考系统同时监听两者以确保不遗漏。

## 六、诚信承诺弹窗

### 6.1 功能定位

诚信承诺弹窗是考试开始前的威慑性提示，要求考生在开始考试前确认承诺。

### 6.2 核心特性

- **不可关闭**：弹窗无关闭按钮，必须勾选承诺后才能进入考试
- **强制确认**：考生需勾选"我承诺独立完成考试，不作弊"选项
- **法律声明**：展示考试纪律与作弊后果的说明文字
- **视觉威慑**：使用严肃的视觉设计，包含签名区域

### 6.3 交互流程

```
考试页面加载
    ↓
诚信承诺弹窗（全屏遮罩）
    ↓
展示承诺文本 + 纪律说明
    ↓
考生阅读 → 勾选"我已阅读并承诺"
    ↓
"开始考试"按钮激活
    ↓
点击后进入考试 → 启动 useMonitor
```

### 6.4 与监考系统联动

诚信承诺的勾选行为可记录为监考事件的一部分，用于在 HR 端展示考生的承诺确认状态，增强监考证据链的完整性。
