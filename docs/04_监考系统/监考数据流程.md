# 监考数据流程

## 一、端到端数据流

监考系统的数据流从前端事件捕获开始，经过多层处理后最终存储到数据库并在 HR 端展示。以下是完整的端到端流程。

### 1.2 流程说明

| 阶段 | 负责模块 | 关键操作 |
|------|----------|----------|
| ① 事件捕获 | useMonitor.js | 监听浏览器原生事件 |
| ② 合并去重 | scheduleAction | 100ms 合并 + 500ms 去重 |
| ③ 事件执行 | onPageLeave/onPageReturn | 计算时长、标记 tags |
| ④ 数据统计 | ref 变量 | leaveCount、totalHiddenDuration |
| ⑤ 持久化 | sessionStorage | 实时写入，防止丢失 |
| ⑥ 提交上报 | flushEvents | 汇总数据，HTTP POST |
| ⑦ 后端存储 | save_monitor_data | 写入 exam_monitor_summary 表 |
| ⑧ 风险分析 | analyze_monitor_behavior | 执行 5 项检测规则 |
| ⑨ 等级计算 | _generate_monitor_analysis | 确定风险等级 |
| ⑩ HR 展示 | GradingResultDetail.vue | 时间线 + 摘要 + 建议 |

## 二、前端数据结构

### 2.1 运行时状态（ref）

运行时状态存储在 Vue 3 的 `ref` 中，用于实时追踪监考状态。

```javascript
// useMonitor.js 核心状态
const isMonitoring = ref(false);        // 监考是否激活
const isPageHidden = ref(false);        // 页面当前是否隐藏
const leaveCount = ref(0);              // 离开页面次数
const totalHiddenDuration = ref(0);     // 总离开时长（毫秒）
const currentHiddenStart = ref(null);   // 当前离开开始时间戳
const events = ref([]);                 // 完整事件列表（≤100 条）
```

| 字段 | 类型 | 初始值 | 说明 |
|------|------|--------|------|
| `isMonitoring` | `boolean` | `false` | 监考是否正在运行 |
| `isPageHidden` | `boolean` | `false` | 页面当前是否处于 hidden 状态 |
| `leaveCount` | `number` | `0` | 累计离开次数 |
| `totalHiddenDuration` | `number` | `0` | 累计离开时长（毫秒） |
| `currentHiddenStart` | `number \| null` | `null` | 当前离开开始时间戳 |
| `events` | `Array` | `[]` | 完整事件列表，上限 100 条 |

### 2.2 环境数据

环境数据在考试开始时采集，用于后续 HR 端展示和风险分析。

```javascript
const environmentData = {
  device: 'desktop',           // 设备类型：desktop / mobile / tablet
  screen: {
    width: 1920,
    height: 1080,
    colorDepth: 24
  },
  network: {
    online: true,
    type: 'wifi'               // 网络类型（如果可获取）
  },
  browser: {
    name: 'Chrome',
    version: '120.0'
  },
  orientation: 'portrait'      // 初始方向
};
```

| 字段 | 说明 |
|------|------|
| `device` | 设备类型，用于判断是否为移动端 |
| `screen` | 屏幕分辨率与色深 |
| `network` | 网络初始状态 |
| `browser` | 浏览器信息 |
| `orientation` | 初始屏幕方向 |

### 2.3 独立事件存储

方向事件和网络事件独立存储，提交时合并到完整事件流中。

```javascript
const orientationEvents = ref([]);   // 方向变化事件
const networkEvents = ref([]);      // 网络状态事件
```

**独立存储的理由：**
- 减少主事件数组的复杂度
- 提交时可以灵活合并或单独上报
- 便于后续扩展新的事件类型

### 2.4 持久化结构（sessionStorage JSON）

每次事件发生后，系统会将完整状态序列化写入 `sessionStorage`。

**存储 Key 格式：**
```
exam_monitor_{recordId}
```

**存储内容示例：**

```json
{
  "version": 1,
  "events": [
    {
      "type": "exam_leave",
      "timestamp": 1729000000000,
      "tags": []
    },
    {
      "type": "exam_return",
      "timestamp": 1729000003200,
      "duration": 3200,
      "tags": ["rapid_leave_return"]
    }
  ],
  "orientationEvents": [
    {
      "type": "orientation_change",
      "from": "portrait",
      "to": "landscape",
      "timestamp": 1729000010000
    }
  ],
  "networkEvents": [
    {
      "type": "network_offline",
      "timestamp": 1729000020000
    }
  ],
  "leaveCount": 2,
  "totalHiddenDuration": 3200,
  "currentHiddenStart": null,
  "isPageHidden": false,
  "savedAt": 1729000030000
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | `number` | 数据格式版本号，用于后续迁移 |
| `events` | `Event[]` | 主事件列表 |
| `orientationEvents` | `Event[]` | 方向变化事件列表 |
| `networkEvents` | `Event[]` | 网络事件列表 |
| `leaveCount` | `number` | 离开次数（冗余存储，加速恢复） |
| `totalHiddenDuration` | `number` | 总离开时长（冗余存储） |
| `currentHiddenStart` | `number \| null` | 当前离开的开始时间（异常恢复用） |
| `isPageHidden` | `boolean` | 页面是否隐藏（异常恢复用） |
| `savedAt` | `number` | 最后保存的时间戳 |

### 2.5 数据持久化读写流程

```
读取（startMonitoring 时）：
    sessionStorage.getItem(key)
        │
        ├── 存在 → JSON.parse → 恢复状态
        │                    │
        │                    ├── currentHiddenStart !== null
        │                    │   → 生成 leave_recovered 补偿事件
        │                    │
        │                    └── 恢复完成，清空补偿标记
        │
        └── 不存在 → 初始化空状态

写入（每次事件后）：
    1. 构建完整状态对象
    2. JSON.stringify
    3. sessionStorage.setItem(key, jsonString)

清理（提交成功后）：
    sessionStorage.removeItem(key)
```

### 3.2 数据写入流程

```

    │
    ▼
ExamRecordService.save_monitor_data(exam_record_id, monitor_data)
    │
    ├── 解析 monitor_data
```

## 四、提交后清理策略

### 4.1 提交成功

```
submitExam() 成功
    │
    ▼
flushEvents() 上报监考数据
    │
    ▼
HTTP POST → save_monitor_data()
    │
    ▼
后端返回成功
    │
    ▼
clearPersistedData()
    ├── sessionStorage.removeItem(`exam_monitor_${recordId}`)
    ├── 重置所有 ref 状态
    └── 标记已提交
```

**清理后状态：**
- sessionStorage 中的监考数据被清除
- 前端 ref 状态重置为初始值
- 后续无法重新提交（防止重复上报）

### 4.2 提交失败

```
submitExam() 失败
    │
    ├── 网络错误 / 服务器错误
    │
    ▼
保留 sessionStorage 缓存
    ├── 数据完整保留
    ├── leaveCount / totalHiddenDuration 保留
    └── 下次进入时可恢复
    │
    ▼
提示用户重新提交
    │
    ▼
用户点击"重新提交"
    │
    ▼
flushEvents() → 再次尝试上报
```

**失败恢复机制：**
- 缓存不会因提交失败而丢失
- 考生重新进入考试时会自动恢复
- `leave_recovered` 机制确保异常中断也能补偿

### 4.3 多次提交保护

| 场景 | 处理 |
|------|------|
| 首次提交成功 | 清除缓存，标记已提交 |
| 网络超时 | 保留缓存，允许重试 |
| 重复提交（前端重复点击） | 后端通过 `exam_record_id` 唯一约束防止重复写入 |

## 五、多标签页隔离

### 5.1 隔离机制

监考数据严格按照考试记录 ID 进行隔离存储，确保多标签页场景下的数据独立性。

**隔离 Key 格式：**
```
exam_monitor_{recordId}
```

### 5.2 场景分析

| 场景 | 行为 | 结果 |
|------|------|------|
| 同考生打开多个考试标签页 | 每个标签页独立监考 | 各自记录各自的事件，互不影响 |
| 同一考试记录 ID | 各标签页的 key 相同 | sessionStorage 数据可能被覆盖（设计预期：一次考试只在一个标签页中完成） |
| 不同考试记录 ID | 各标签页 key 不同 | 完全隔离，互不影响 |

### 5.3 设计约束

- **单标签页原则**：一场考试应在单一标签页中完成，通过诚信承诺和 UI 提示引导考生
- **sessionStorage 隔离**：sessionStorage 按浏览器标签页隔离，天然支持多标签页独立
- **后端唯一性**：`exam_monitor_summary.exam_record_id` 设置唯一约束，防止重复存储

### 5.4 数据一致性保障

```
考生在标签页 A 开始考试 → exam_monitor_record_001 写入
    │
    ├── 切换到标签页 B 进入同一考试
    │   → 检测到已有 sessionStorage 数据
    │   → 加载标签页 A 的监考状态（可能导致状态不一致）
    │
    ▼
推荐：一次考试只在一个标签页中完成
    → 通过考前提示 + 技术手段约束
    → 避免多标签页导致的数据歧义
```

## 六、数据提交接口

### 6.1 请求格式

```
POST /api/exam/{examRecordId}/submit

Request Body:
{
  "answers": { ... },              // 答题数据
  "monitorData": {
    "events": [                     // 完整事件列表
      {
        "type": "exam_leave",
        "timestamp": 1729000000000,
        "tags": []
      }
    ],
    "orientationEvents": [...],      // 方向变化事件
    "networkEvents": [...],         // 网络事件
    "stats": {
      "leaveCount": 5,
      "totalDuration": 125000       // 毫秒
    },
    "environment": {                // 环境信息
      "device": "desktop",
      "screen": { ... },
      "browser": { ... }
    }
  }
}
```

### 6.2 响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "submitted": true,
    "monitorSaved": true,
    "riskLevel": "medium",
    "reviewSuggestion": "存在中度异常行为，建议人工复核离开期间的答题内容"
  }
}
```

### 6.3 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `events` | `Event[]` | 主事件列表，包含 exam_leave、exam_return、leave_recovered、refresh_attempt 等 |
| `orientationEvents` | `Event[]` | 独立的方向变化事件列表 |
| `networkEvents` | `Event[]` | 独立的网络事件列表 |
| `stats.leaveCount` | `number` | 累计离开次数 |
| `stats.totalDuration` | `number` | 累计离开时长（毫秒） |
| `environment` | `Object` | 考试环境信息 |
