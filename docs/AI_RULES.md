# 1. 项目业务定位规则

## 项目名称
AI考试系统（企业内部版）

## 核心定位
本项目为**企业内部 AI 智能考试与测评系统**，服务于企业人事部门。

## 核心流程
```
HR 创建考试 → 发布考试 → 员工参加考试 → 自动评分 → AI 生成分析报告 → HR 查看结果
```

## 功能范围
- 考试创建 / 发布 / 管理
- 员工在线考试
- 客观题自动评分
- AI 主观题评分
- AI 考试分析报告
- HR 成绩管理

## 所有新增功能必须服务于该流程

# 2. 用户角色规则

## 系统角色定义

### 管理员
- 负责：系统维护、用户管理

### HR（核心角色）
- 负责：创建考试、管理考试、查看全部成绩、查看 AI 报告

### 员工
- 负责：登录系统、参加考试、查看个人结果

## 禁止设计
- 部门主管角色
- 部门管理员
- 多级审核角色
- 候选人（Candidate）角色（内部考试场景不需要）

# 3. 考试设计规则

## 固定试卷模式
考试采用**固定试卷模式**，规则如下：
- 每场考试题目固定
- HR 负责配置试卷（手动创建 + JSON 导入）
- 员工完成统一考试

## 禁止默认设计
- 随机抽题
- 随机组卷
- 动态难度组卷
- 自动生成试卷

## 未来扩展
如未来需要扩展考试模式，必须经过产品确认。

# 5. 架构约束

## Backend 分层架构

```
API (api/v1/endpoints/)
    ↓
Schema (schemas/)
    ↓
Service (services/)
    ↓
Model (models/)
    ↓
Database (db/)
```

### 规定
1. **API 层禁止直接操作数据库**
   - API 层只做：参数校验、调用 Service、返回响应
   - 所有数据库操作必须通过 Service 层

2. **Service 层禁止处理 HTTP 逻辑**
   - Service 层只做：业务逻辑、数据持久化、事务管理
   - 不处理 HTTP 状态码、请求/响应格式

3. **统一响应格式**
   - 所有 API 响应使用 `ApiResponse` 格式
   - 使用 `success()` / `error()` / `created()` 等工具方法

4. **统一异常处理**
   - 使用 `AppException` 体系（NotFoundException / BusinessException / ValidationException / ForbiddenException / UnauthorizedException）
   - 禁止直接抛出 `HTTPException`

## Frontend 分层架构

```
页面 (views/)
    ↓
组件 (components/)
    ↓
Store (stores/)
    ↓
API 封装 (api/)
```

### 规定
1. **页面禁止直接调用 axios**
   - 所有 HTTP 请求必须通过 `api/` 模块封装
   - 页面只调用 `api/` 中导出的方法

2. **组件职责单一**
   - 组件只负责 UI 渲染和用户交互
   - 业务逻辑放在 Store 或 composables 中

3. **状态管理使用 Pinia**
   - 全局状态（用户信息、考试信息）必须放在 Pinia Store
   - 组件内状态使用 `ref` / `reactive`

# 6. 数据库规范

## 必备字段
所有业务表必须包含：
- `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
- `updated_at` DATETIME NOT NULL ON UPDATE CURRENT_TIMESTAMP

## 数据库修改规则
1. **必须通过 Alembic migration**
   - 禁止直接修改生产数据库
   - 所有结构变化必须创建 Alembic 迁移文件

2. **迁移文件命名规范**
   - 使用有意义的哈希前缀，如 `e1f2a3b4c5d6_add_xxx.py`
   - 文件名描述修改内容

3. **JSON 字段统一**
   - 使用通用 `sa.JSON()` 类型
   - 禁止使用 MySQL 特有 `JSON` 类型

## 命名规范
- 表名：小写 + 下划线，如 `exam_record`
- 主键：统一 `id BIGINT AUTO_INCREMENT`
- 外键：`{目标表名}_id`，如 `exam_id`
- 索引前缀：`idx_`，唯一索引加 `UNIQUE`

# 7. AI 功能开发规则

## Prompt 管理规则
1. **所有 AI Prompt 必须独立管理**
   - 存放于 `ai-service/app/prompts/{功能}/`
   - 示例：`ai-service/app/prompts/scoring/`、`ai-service/app/prompts/report/`

2. **Prompt 必须版本化**
   - 命名：`v1.yaml`、`v2.yaml`
   - 修改 Prompt 时创建新版本，禁止覆盖已验证的 Prompt

3. **Prompt 输出必须结构化**
   - 优先使用 JSON 格式输出
   - 定义清晰的字段名和类型
   - Agent 必须对 AI 返回的 JSON 进行解析和校验

4. **AI 结果必须记录元信息**
   - 记录使用的模型名称
   - 记录使用的 Prompt 版本
   - 记录评分置信度（confidence）
   - 记录生成状态（success/failed）

## AI Agent 规范
1. **Agent 必须继承 BaseAgent**
   - 实现 `run()` 方法
   - 实现 `validate_input()` 方法
   - 处理 LLM 调用异常

2. **JSON 解析必须健壮**
   - 支持代码块格式（```json ```）
   - 支持文本前缀提取
   - 支持嵌套结构（追踪大括号匹配）
   - 解析失败时有降级方案

3. **类型修正和标准化**
   - 对 AI 返回的字段进行类型修正（list/dict）
   - 对枚举值进行标准化
   - 返回默认值而非抛异常

## AI 调用规范
1. **Backend 调用 AI-Service 必须通过独立 Service**
   - 封装 HTTP 调用为独立方法
   - 支持超时处理（30 秒）
   - 支持响应格式校验

2. **AI 失败必须有完备的异常处理**
   - 服务不可用 → 降级处理
   - 超时 → 返回默认结果
   - 返回格式错误 → 尝试修复或降级
   - 必须记录错误日志

## AI 数据安全访问规则

### 数据分级标准
系统数据按敏感程度分为四级，AI Agent 访问必须遵守以下规则：

| 等级 | 定义 | AI 访问权限 | 示例 |
|------|------|------------|------|
| **L1 极高敏** | 涉及身份认证或财务 | **绝对禁止 AI 访问** | 密码哈希、成本价格、财务数据 |
| **L2 高敏** | 涉及个人隐私或机密 | **脱敏后可访问** | 候选人联系方式、评分结果、AI 原始数据 |
| **L3 中敏** | 涉及业务规则或配置 | **授权后可访问** | 标准答案、评分规则、AI 报告内容 |
| **L4 低敏** | 公开或通用信息 | **允许 AI 访问** | 考试标题、岗位名称、题目内容 |

### AI 数据访问约束

1. **AI Agent 禁止直接访问数据库**
   - 必须通过 Backend Service 层获取数据
   - Backend 负责数据脱敏和权限校验

2. **AI Agent 访问 L2 数据必须脱敏**
   - 候选人姓名：可使用，禁止关联其他身份信息
   - 候选人联系方式：**绝对禁止** AI 访问
   - AI 报告原始数据：**绝对禁止** AI 访问

3. **AI Agent 访问 L3 数据必须授权**
   - 标准答案：仅在评分场景可访问
   - 评分规则：仅在评分/报告生成场景可访问
   - AI 报告内容：仅在报告生成场景可访问

4. **允许 AI Agent 直接访问的 L4 数据**
   - 考试基本信息（标题、岗位、描述）
   - 题目内容（题干、选项）
   - 考试状态、评分状态

### AI 调用权限约束

1. **AI Agent 必须通过 Backend 鉴权**
   - AI 调用必须携带有效用户身份
   - 必须校验用户角色权限
   - 记录 AI 操作审计日志

2. **AI Agent 禁止越权访问**
   - 不得访问其他 HR 创建的考试数据
   - 不得访问未授权的评分/报告数据
   - 不得绕过权限校验直接调用 Service

3. **AI Agent 输出必须经过校验**
   - AI 返回内容必须符合预期格式
   - AI 不得输出系统 Prompt 或内部规则
   - AI 输出不得包含敏感数据

### RAG 知识库数据准入规则

未来接入 RAG 时，知识库内容必须满足：

1. **仅包含 L3/L4 级数据**
   - 考试规则、评分标准
   - 常见问题及解答
   - 非敏感业务流程文档

2. **禁止包含 L1/L2 级数据**
   - 用户信息、联系方式
   - 评分结果、AI 原始报告
   - 任何可能暴露内部实现的信息

# 8. 代码开发规则

## 数据库
- 必须通过 Alembic migration 修改
- 禁止直接修改生产数据库
- 迁移文件必须包含完整的 upgrade/downgrade

## 接口
- API 变更必须同步更新代码
- API 变更必须同步更新 API 文档
- 统一响应格式：ApiResponse
- 统一前缀：/api/v1

## 日志
- 使用统一 logger（禁止 print）
- 日志文件：backend.log / ai_service.log
- 禁止记录密码、API Key、Token 等敏感信息

## 安全
- 密码必须使用 bcrypt 哈希
- 密钥必须使用环境变量
- 所有 HR 端点必须鉴权
- 禁止绕过权限校验

# 12. 禁止事项

## 通用禁止
1. **禁止未经确认重构已有模块**
   - 重构必须有充分理由并获得用户确认
   - 不得随意修改已确定的架构

2. **禁止重复创建已有功能**
   - 开发前必须检查现有代码
   - 如果功能已存在，应扩展而非重写

3. **禁止提前开发未规划模块**
   - 严格遵循当前阶段开发
   - 不得跨阶段提前实现未来功能

4. **禁止引入未经确认技术**
   - 新框架、新库、新工具必须获得用户确认
   - 保持技术栈一致性

## MVP 阶段禁止
以下功能在 MVP 阶段禁止开发：
- **RAG（检索增强生成）**
- **复杂 Agent 编排**
- **AI 监考**
- **Word 文档解析**
- **Docker 生产部署（S4 阶段）**

## 安全禁止
- **禁止明文存储密码**（必须使用 bcrypt 哈希）
- **禁止在代码中硬编码密钥**（必须使用环境变量）
- **禁止在日志中记录敏感信息**
- **禁止绕过权限校验**（所有 HR 端点必须鉴权）
