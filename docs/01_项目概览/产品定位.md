# 产品定位

## 用户角色

系统面向三类核心用户角色：

| 角色 | 核心职责 |
|------|----------|
| **管理员** | 系统维护、用户管理、权限配置 |
| **HR** | 核心角色：创建考试、管理考试、查看成绩、查看 AI 分析报告 |
| **员工** | 参加考试、查看个人成绩与反馈 |

## 核心流程

```
HR 创建考试 → 发布考试 → 员工参加考试 → 自动评分 → AI 生成分析报告 → HR 查看结果
```

### 流程说明

1. **HR 创建考试**：录入考试基本信息，导入或手动添加题目
2. **发布考试**：设置考试时间、参考人员，发布后考生可访问
3. **员工参加考试**：通过手机或 PC 网页进行在线答题
4. **自动评分**：客观题即时评分，主观题由 AI 自动批改
5. **AI 生成分析报告**：对考试结果进行多维度分析，生成报告
6. **HR 查看结果**：查看成绩详情、监考记录、AI 报告与统计数据

## 设计原则

| 原则 | 说明 |
|------|------|
| **固定试卷模式** | 每场考试使用固定的一套试卷，所有考生题目相同，保证公平性与评分可复现 |
| **嵌入式身份** | 考生无需独立账号体系，通过姓名+手机号验证身份，降低使用门槛 |
| **HR 统一管理** | 所有考试相关操作（创建、发布、评分、查看）统一由 HR 角色完成 |
| **AI 能力独立部署** | AI 评分与报告能力作为独立模块部署，便于模型迭代与扩展 |
| **聚焦核心流程** | MVP 阶段聚焦考试创建→评分→报告的核心链路，不做过度设计 |

## 【已废弃】的功能

以下功能在 MVP 阶段明确排除，后续可根据实际需要再行评估：

| 废弃功能 | 废弃原因 |
|----------|----------|
| 随机抽题 | 固定试卷模式已满足业务需求，随机抽题增加系统复杂度 |
| 自动组卷 | 由 HR 手动创建试卷更符合企业考试场景，灵活且可控 |
| 动态难度组卷 | MVP 阶段无需，后续可根据大规模数据积累再评估 |
| 候选人角色 | 当前业务场景仅覆盖内部员工，候选人场景留待二期 |
| 部门主管权限 | HR 统一管理模式下不需要部门主管权限，简化权限体系 |
| RAG 知识库 | MVP 阶段禁止引入 RAG，AI 能力直接调用大模型即可 |
