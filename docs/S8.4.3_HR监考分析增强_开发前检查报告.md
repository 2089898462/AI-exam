### 1.2 必须修复（Blocker）

> **B-1: Schema 字段缺失导致前端拿不到 behavior_tags 和 behavior_details**

**现状**:
- 后端 `grading_service.py` 的 `get_grading_result_detail()` 方法返回的 dict 包含 `behavior_tags` 和 `behavior_details`
- 但 Pydantic Schema `MonitorAnalysisResponse` 未声明这两个字段
- FastAPI 使用 `response_model=GradingResultDetailResponse` 时会**自动过滤掉未声明的字段**

**影响**:
- 前端 `monitorAnalysis.behavior_tags` 始终为 `[]`
- 前端 `monitorAnalysis.behavior_details` 始终为 `[]`
- S8.4.2 开发的异常标签展示功能**实际未生效**

**修复方案**:
在 `MonitorAnalysisResponse` 中补充字段声明：
```python
behavior_tags: list = Field(default_factory=list, description="异常行为标签列表")
behavior_details: list = Field(default_factory=list, description="异常行为详情列表")
```

## 3. 存在问题分析

### 3.1 P0 - Schema 字段缺失（必须修复）

**问题**: `MonitorAnalysisResponse` 未声明 `behavior_tags` 和 `behavior_details`

**根因**: S8.4.2 开发 Service 层时增加了返回字段，但忘记同步更新 Pydantic Schema

**影响**:
- S8.4.2 前端展示的「异常行为标签」和「异常行为详情」始终为空
- HR 看到的监考分析只有核心指标，看不到具体的异常标签

**修复工作量**: 5 分钟（加 2 行声明）

### 3.2 P1 - 列表页无风险标识

**问题**: `GradingResultList.vue` 评分列表页无风险等级列

**影响**:
- HR 审核时需逐条点开详情页才能看到监考状态
- 无法在列表中快速定位高风险记录
- 高风险和正常记录混在一起，审核效率低

**建议**: 列表页增加「监考风险」列，显示风险等级 Tag

### 3.3 P2 - 异常展示形式

**问题**: 当前事件表格信息密度高，不够直观

**现状**:
```
| 时间 | 事件类型 | 持续时间 | 异常标签 | 详情 |
|------|----------|----------|----------|------|
| 2026-08-20 10:20 | 页面离开 | 30秒 | 高频离开 | - |
| 2026-08-20 10:25 | 网络断开 | - | - | - |
```

**建议**: 改为时间线形式
```
⏱️ 10:20:01  页面离开  持续30秒  [📊 高频离开]
⏱️ 10:25:10  网络断开  [📡 网络相关]
⏱️ 10:26:00  页面返回  持续5分钟 [⏱️ 长时间离开]
```

### 3.4 P3 - 移动端体验

**问题**: 小屏幕下表格列太多，横向滚动才能看全

**现状**: `@media (max-width: 768px)` 只处理了间距，未处理表格

**影响**: HR 在手机上审核体验差

## 4. 推荐 UI 优化方案

### 4.1 风险摘要卡片（推荐位置：监考信息卡片顶部）

在现有监考信息卡片中增加摘要区域：

```
┌─────────────────────────────────────────────┐
│ 监考信息                    [中风险]        │
├─────────────────────────────────────────────┤
│ ⚠️ 考试期间5次离开页面                       │
│ ⚠️ 存在1次超过5分钟离开                     │
│ ℹ️ 部分离开与网络异常相关                   │
├─────────────────────────────────────────────┤
│ [风险等级] [离开次数] [累计时长]            │
│  中风险     5次       320秒                 │
└─────────────────────────────────────────────┘
```

**优点**:
- 一句话告诉 HR 是否有问题
- 列出最关键的 2-3 条异常
- 保持现有指标不变

### 4.2 异常标签展示（已实现，需修复 Schema 后生效）

当前 S8.4.2 已实现，修复 Schema 后自动生效：

```
异常行为识别
[⚡ 快速返回] [⏱️ 长时间离开] [📊 高频离开] [📡 网络相关]
```

### 4.3 关键指标展示（已实现）

```
考试时长    离开占比    最长离开    平均离开
45分30秒   11.7%      300秒      64.0秒
```

### 4.4 异常时间线（建议新增，替代现有表格）

**评估**:
| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| 保留现有表格 | 实现成本低 | 信息不直观 | - |
| 改为时间线 | 直观易读 | 实现稍复杂 | ✅ 推荐 |
| 两者并存 | 可切换 | 维护成本高 | 不推荐 |

**时间线设计**:
```
📅 异常行为时间线

● 10:05:00  页面离开  [📡 网络相关]  持续10秒
● 10:12:30  页面离开  [📊 高频离开]  持续5秒
● 10:13:10  页面离开  [📊 高频离开]  持续8秒
● 10:14:00  页面离开  [📊 高频离开]  持续300秒 [⏱️ 长时间离开]
● 10:20:00  网络断开
● 10:21:30  页面离开  [📡 网络相关]  持续15秒
```

**实现方式**: 使用 Element Plus `el-timeline` 组件

### 4.5 HR 审核建议（建议新增）

**原则**: 不做判断，只给建议

```
💡 系统建议
高风险：建议人工复核答题情况
中风险：建议抽查关键答题时段
```

**实现**: 后端根据 `risk_level` 生成建议文案，前端 Alert 展示

### 7.1 需求评估

### 7.2 方案对比
