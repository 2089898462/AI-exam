## 4. 关键关系说明

### 4.1 候选人嵌入式身份设计
- 系统**无独立 candidate 表**
- 候选人身份通过 `user.role = 'candidate'` 标记
- 候选人在 `exam_record` 中以"嵌入字段"形式存储（避免多表联查）

### 4.2 主业务链路
```
一场考试 (exam)
  │ 1:N
  ▼
多条考试记录 (exam_record)          ← 每位候选人/每场考试一条
  │ 1:N
  ▼
多条答题记录 (answer_record)        ← 每道题一条
  │
  │ 1:1
  ▼
一条评分记录 (grading_record)
  │
  │ 1:1
  ▼
一份 AI 报告 (ai_report)
```

### 4.3 可选关系
- 每场考试**可选**指定参与者（`exam_participant`）
- 监考汇总（`exam_monitor_summary`）与 `exam_record` 为 1:1 可选关系
- `candidate_analysis_report` 按候选人聚合多场考试结果

## 5. 数据库迁移规则

1. **Alembic 管理**：所有结构变更必须通过 Alembic 脚本完成，禁止手工改表。
2. **禁止直接修改生产库**：生产环境只允许通过 `alembic upgrade head` 执行迁移。
3. **迁移脚本规范**：
   - 文件名：`YYYYMMDD_HHmm_描述.py`
   - 必须包含 `upgrade()` 与 `downgrade()`
   - 涉及数据变更时需写清回滚策略
4. **JSON 字段类型**：统一使用 `sa.JSON()`（通用类型），避免 MySQL 专有类型导致迁移困难。
5. **必备字段**：每张业务表必须包含：
   - `created_at`：创建时间（`DateTime`，默认 `func.now()`）
   - `updated_at`：更新时间（`DateTime`，自动更新）

## 6. 索引与性能建议

- 高频查询字段（如 `exam_record.exam_id`、`answer_record.record_id`）必须建立外键或普通索引。
- 状态字段（如 `grading_record.status`）可根据查询频率建立联合索引。
- JSON 字段（`events_json` 等）不做索引，仅用于审计与展示。
- 大表查询建议分页（`LIMIT/OFFSET`），避免全表扫描。
